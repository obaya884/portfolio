# 社会人ポートフォリオ 計画書

2026-11-07 時点の合意事項。作り始める前に「未決事項」を本人と詰める。

## 背景

このリポジトリのサイトは、学生時代（2020年時点）の内容で止まっている。今の自分を表すサイトを作り、今のサイトは2020年版として残す。

## 目的

見てほしい人は、見知らぬ人や SNS でのつながり。

見た人に期待すること:

- エンジニアとして尊敬してもらえる
- リファラルなど、転職の声をかける相手のプールに入る
- 副業案件の相談につながる

応募書類のように読み込まれるのではなく、偶然たどり着いた人が短時間で判断する前提で考える（記述者の推測。本人未確認）。

## 構成

1つのリポジトリ（`obaya884/portfolio`、名前は変えない）で、2つのサイトを公開する。

| | 社会人版 | 2020年版（学生） |
|---|---|---|
| 今の URL | `https://obaya884.github.io/portfolio/` | `https://obaya884.github.io/portfolio/2020/` |
| ドメイン取得後 | `https://<ドメイン>/` | `https://<ドメイン>/2020/` |
| 扱い | 制作を進める | 内容を凍結 |

今の `/portfolio/` へのリンクは社会人版を開くようになる。

## やらないこと

- **独自ドメインの取得は今はしない。** 今後も使える名前を決めきれていないため。
- **2020年版の作り直しはしない。** 下記の案内とリンクの追加だけにとどめる。

## 進める順番

1. この計画書をリポジトリに置く。
2. 未決事項を詰め、社会人版を制作する。master へのマージがそのまま公開になるので、完成までは 2020年版を `/portfolio/` に出したまま、トピックブランチで作業する（記述者の判断）。
3. 社会人版の公開と同時に、2つのサイトをつなぐ。
   - 2020年版を `/2020/` に移す。
   - 社会人版に2020年版へのリンクを置く。
   - 2020年版に「これは2020年版です」という案内と、社会人版へのリンクを足す。

## 2020年版の持ち方

ビルド済みのファイルを `/2020/` に静的に置く（記述者の判断）。古いコードの依存を抱えないので、凍結したサイトに Dependabot のアラートが出ない。元のコードは git の履歴に残す。`vite.config.ts` の `base: "./"` によりアセットは相対パスなので、配下へ移しても動く見込み（未検証。移すときに確認する）。

`index.html` の `og:url` と `og:image` は絶対 URL なので、移すときに直す。

## 将来の独自ドメイン

名前が決まったら後から取得できる。このリポジトリに独自ドメインを設定すると、社会人版はそのドメインのルートに移り、`obaya884.github.io/portfolio/` は GitHub がそのドメインへ転送する。絶対 URL（`og:url` など）は設定時に直す。

2020年版を `2020.<ドメイン>` のようなサブドメインにするには、別のリポジトリが要る。GitHub Pages の独自ドメインは1リポジトリに1つのため。1リポジトリのままなら `<ドメイン>/2020/` になる。

## 未決事項（本人が決める）

重要な順。

1. **見せる仕事。** 「この仕事を見せたら尊敬される」と思える今の仕事や作ったもの。社外秘で書けないものは、どこまで書けるかも含めて確認する。サイトの中身と構成はこれで決まる。
2. **転職や副業に前向きなことを公開で書くか。** 公開サイトなので、今の勤務先や同僚の目にも触れる。副業が勤務先の規定で認められているかも確認する。「相談歓迎」と明記するか、実績と連絡先を置くだけにするかで、文面と導線が変わる。
3. **連絡の受け方。** メール、SNS の DM、フォームのどれで受けるか。フォームには外部サービスが要るので、2020年版の「サードパーティへのリクエストゼロ」を新サイトでも守るかと合わせて決める。
4. **3つの目的の優先順位と、読まれ方の想定。** 尊敬、転職、副業のどれを先頭に置くか。上の「短時間で判断する」という推測が正しいか。短い1画面で伝える構成と、事例を読み込ませる構成では、情報設計が別物になる。
5. **別リポジトリの作品を載せるか。** hitosuji、Re-Buy、bassdrill を公開してよいか。載せるなら、リンクだけか、スクリーンショットや技術解説も載せるか、ソースコードも見せるか。
6. **個人情報の出し方。** 本名をどこまで出すか、生年月日を載せるか。2020年版には本名とフルの生年月日が載っていて、同じサイト内に置くので社会人版だけ伏せても意味がない。2020年版から外す場合は、公開リポジトリの git 履歴まで消すかと、公開と同時か先に単独で外すかも決める。
7. **見た目の方向性。** 参考にしたいサイトや、避けたい印象。2020年版のデザイン（squircle、配色）を引き継ぐかどうかも含む。
8. **言語。** 日本語だけでよいか、英語でも読めるようにするか。特に希望が無ければ日本語のみを既定とする（記述者の判断）。英語は後からでも足せる。

## 作り手に任せること

ページ構成の細部と実装の進め方。技術スタックは、このリポジトリの Vite + React + TypeScript と GitHub Actions でのデプロイをそのまま使うのが既定（記述者の判断）。公開時に `CLAUDE.md` を新しい構成に合わせて書き直す。
